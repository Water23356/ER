# ER.Entity2D 系统

## 概述
该系统是一个用于2D游戏开发的实体行为控制框架，通过一系列代理器、状态机、动作控制器等组件，实现了对游戏实体行为的灵活管理和控制。它能够处理实体的受伤、攻击、状态转换等多种行为，为2D游戏的开发提供了强大的支持。

## 核心组件

### 代理器（Agents）
- **ActionAgent**：动作代理器，用于管理实体的动作行为，如注册、注销动作，触发和中断动作等。
- **ControllerAgent**：控制代理器，负责管理实体的控制器，实现对实体行为的控制。
- **EntityAgent**：实体代理器，是基本实体事件的作用对象，处理伤害传递、Buff传递等事件。
- **StateAgent**：状态代理器，管理实体的状态，如注册、注销状态，获取特定状态等。
- **StateMahinceAgent**：状态机代理器，负责状态间的跳转管控，通过设置参数和触发器来控制状态转换。

### 状态与动作
- **StateBase**：状态基类，定义了状态的基本属性和方法，如进入、离开状态的逻辑。
- **ActionBase**：动作基类，抽象类，定义了动作的基本行为，如初始化、进入、离开动作等。
- **ControllerBase**: 控制器基类, 负责定义输入层到模型层的数据传输: 
    1. 向相关组件传递输入信息
    2. 向状态机代理 (**StateMachineAgent**) 传递状态信息 或 直接触发对应组件
- **ActionControllerBase**：单一动作控制器基类，**ControllerBase** 特化积累, 专门针对单一动作的控制
    1. 向相关动作对象传递输入信息
    2. 向状态机代理 (**StateMachineAgent**) 传递状态信息 或 直接触发对应动作 (**UpdateActionControlState(bool)** 方法)

### 伤害处理
- **HitSource**：击打事件源抽象类，定义了发送击打事件和处理反馈信息的接口。
- **HitSourceGroup**：击打事件源组，对事件源进行成组封装，管理多个击打事件源。
- **HurtHandler**：受伤处理器，处理实体受到的伤害，如计算伤害、应用效果等。
- **HitReplySource**：伤害反馈源抽象类，响应伤害事件，提供反馈信息。

### 碰撞与区域检测
- **HitBox**：打击区域类，用于检测与受击箱的碰撞，并触发击打事件。
- **HurtBox**：受击箱类，与打击区域配合使用，标识可受击的区域。
- **Area**：区域基类，定义了进入和离开区域的事件。
- **ColliderFlag**：碰撞标志类，用于标记碰撞对象，辅助区域检测。
- **ColliderGroupArea**：碰撞组区域类，管理一组碰撞对象，实现复杂的碰撞逻辑。
- **SingleArea**：单一区域类，处理简单的区域进入和离开事件。

## 使用方法
1. 在Unity项目中导入该系统的所有脚本文件。
2. 在游戏实体的GameObject上添加相应的代理器组件，如EntityAgent、ActionAgent等。
3. 根据需要添加状态、动作、控制器等组件，并进行配置和脚本编写，实现特定的行为逻辑。
4. 通过脚本调用代理器的方法，如触发动作、改变状态等，来控制游戏实体的行为。

## 注意事项
- 在使用该系统之前，请确保熟悉Unity的组件系统和事件处理机制。
- 该系统的设计较为复杂，涉及到多个组件的协同工作，建议在有一定Unity开发经验的基础上使用。
- 在实际项目中，可能需要根据具体需求对系统进行扩展和定制，如添加新的状态、动作类型等。
